# Refund session report v2

This language-neutral schema describes the existing Python refund-session report, explicitly imported as `(envelope_version=1, source_kind=eval_report, source_schema_version=2)`. It does not replace or change `schemas/evaltest` v1. The backend mirror is `backend/internal/vibe/sdk_schema/refund-report-v2.schema.json`; the parity test compares exact bytes.

The wire authority is the reviewed MCP `contracts.ts` reportSchema and `comparison.ts` validateReport, together with the pinned `agentclash-evals 0.2.0a1` runner/session finalization. Structural JSON Schema validation is necessary but insufficient: the importer also checks report/run identity, unique IDs, supported refund assertions, equality verdicts, paired contiguous turn checks, complete final assertions, invocation/observation flags, required-case coverage, summary counts, failure references and runner exit/status agreement. It does not execute a target, fetch a URL, recompute fixture state or attest that uploaded claims are true.

The platform's existing bounded importer adds a 1 MiB source limit and at most 200 exact source-case mappings, plus the existing 256-byte external report ID storage limit. The canonical wire schema permits 1000 cases and 200 Unicode characters in report IDs; this importer intentionally preserves its existing narrower storage bounds. Actual pinned runner run IDs are at most 128 ASCII letters/digits/underscores/hyphens. The v2 parser also preserves the MCP maximum nesting of 20 and rejects reserved `__proto__`, `prototype` and `constructor` object keys. Other arbitrary JSON under `evidence` (including inert `$ref` keys) remains bounded data; unknown structural fields reject. This format currently specifies `cost_usd: null` and `observations.cost: false`. Incomplete, skipped, config-error, timeout and zero-case reports may be valid; they remain visible with unknown/incomplete diagnostics. V2 does not contain AgentResult-v1 replies and is unsupported for hosted text regrading or expectation promotion.

The four fixtures are actual Linux CI executions of explicitly SCRIPTED synthetic demo refund functions. The directory labels `claude` and `openai` identify demo adapter cohorts, not model execution. Both `faulty-v1` and `correct-v2` are target revisions; all four report files have source schema 2. They are not customer agents, native-model pilot transcripts, or proof of real-user acceptance. Inspection found demo IDs/prompts/tool arguments, synthetic ledger data and the failed-run SDK assertion traceback only. No original bytes were sanitized or modified; `fixtures/SHA256SUMS` records these copied originals. Mutation tests modify in-memory copies. The private frozen evidence remains unchanged.

Source readiness does not mean the deployed service supports v2. Clients must require the explicit additive `sdk_report_import_formats` capability in `/v1/vibe/config`. Real customer-agent report/save acceptance and the corresponding ACQ-07/#8 criterion remain open.
