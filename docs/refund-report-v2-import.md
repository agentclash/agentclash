# Private alpha: saving refund report v2

This is a source-bound import contract. Backend rollout is pending; no current deployed support or live account acceptance is implied. The plugin remains private. Real customer-agent report/save acceptance and ACQ-07/#8 remain open. The included fixtures are actual executions of explicitly scripted synthetic refund functions.

Use the existing authenticated workspace report importer with envelope 1. Supported tuples are `eval_report/1`, `agent_result/1`, and explicit `eval_report/2` for the known refund session format. `agent_result/2`, version relabeling, unknown structural fields and inconsistent reports reject. Existing v1 schemas and behavior are unchanged. GET `/v1/vibe/config` advertises `sdk_report_import_formats`; clients offer v2 only when the exact `(1, eval_report, 2)` tuple is present. Older servers continue to offer v1. Discovery performs no write and never retries v2 as v1.

Choose “Refund session report v2”, read the file, review the allowlisted metadata/case/check preview, and explicitly map every source case to the saved test version before selecting “Import historical report”. Mapping never follows similar IDs automatically. The preview omits raw prompts, replies, tool arguments and tracebacks. **Saving retains the complete original file**, including those fields; it does not silently redact or replace the file. Read permissions and downloads remain restricted by the existing project owner, selected workspace and current active organization membership. Workspace viewers may read their authorized retained evidence but cannot import.

The existing `vibe_sdk_reports.source_json` bytea stores the immutable UTF-8 original. The receipt records its SHA256, source kind/version, original report ID, exact mappings and created time. The per-project external report identity has exact-request idempotency: an identical original and metadata return the original receipt/time without additional storage or success analytics. Changed bytes or metadata conflict rather than overwrite. All retained original bytes and receipt projections consume the shared retained-source quota. No migration or new storage/auth service is introduced.

V2 checks validate report/run identity, unique IDs, known refund assertions, paired turns, required coverage, observations, status/count/failure agreement and runner exit semantics. Valid incomplete, skipped, zero-case and configuration-error reports remain retained with UNKNOWN/incomplete diagnostics. Null cost stays null; capture starts unknown. A capture flag or digest does not prove hosted application execution. Uploaded suite/fixture digest, target identity/revision, check coverage and failures remain visible as uploader claims. If declared application revision or test fingerprint differs from source target revision or suite digest, the receipt surfaces both rather than overwriting either. Exact mapping does not establish equivalent comparison with hosted results.

The ordinary receipt and case APIs expose a version-aware view; the original report is unchanged. V2 checks retain their original `/cases/<index>/checks/<index>` coordinates in observed evidence. Raw fixture/turn/tool evidence is not converted into hosted observations or AgentResult-v1 replies. Authorized users can reopen the receipt, read the source case and download/export the exact original. Hosted text regrading and expectation promotion are unsupported for v2 and disabled in the UI; backend guards reject before compilation, quote/admission or provider work. V1 operations retain their existing behavior.

Verification uses controlled authenticated HTTP/UI fixtures and an owned loopback PostgreSQL with all current migrations. It does not establish WorkOS production ownership, real signup, native model routing, live backend rollout or customer-agent acceptance. The focused Linux browser command is:

```sh
cd web
pnpm exec playwright test -c playwright.vibe-stack.config.ts e2e/vibe-stack/sdk-reports.spec.ts --grep 'refund report v2'
```

Use the existing owned Linux fixture setup (`VIBE_TEST_DATABASE_URL` naming a loopback `vibe_test` database and `VIBE_BROWSER_OWNERSHIP_LOG`). Keep its Linux/subreaper and database ownership guards. Expected evidence is the Playwright result plus exact-source download equality, v2 receipt/reopen identity, explicit mapping, null cost, disabled regrade/promotion and unchanged zero operation/provider-call counts. This importer test starts no SDK target or provider evaluation.
